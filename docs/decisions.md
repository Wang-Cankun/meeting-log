# Decisions

> This document owns rationale. Current behavior belongs to code and tests.

| Decision | Status | Consequence |
|---|---|---|
| Personal macOS 26 app | accepted | No accounts, installer, updater, or backward-compatibility paths |
| Native SwiftUI | accepted | Core Audio, ScreenCaptureKit, AVFoundation, Security, and URLSession remain direct dependencies |
| Configurable AI provider | accepted | One user-entered OpenAI-compatible endpoint, model, and API key serve summary and, without a speech service, transcription; the default endpoint is OpenRouter and the user chooses a model. A provider that rejects `temperature` is retried without it |
| Optional speech service | accepted | Settings explicitly selects AI-provider audio input or Azure Speech with MAI-Transcribe-2. Azure's endpoint and key are separate from the summary provider; diarized segments become `[MM:SS] Speaker:` turns locally. Settings store the key like the provider key |
| Optional AI summaries | accepted | Settings can turn summaries off. Processing then requires Azure Speech, sends nothing to a language model, and archives audio with the raw and locally tidied transcripts only. Folder titles come from the start time (`会议 HHmm`) or the first imported file name. Transcript-only meetings are listed without a summary and are not regenerated; Regenerate is unavailable for every meeting while summaries are off. A saved summary provider is kept but unused |
| Complete setup in Settings | accepted | One Test & save validates JSON output and a generated silent audio upload, then saves both services before resuming pending work. With AI summaries off it validates and saves Azure Speech only. Failed verification keeps the saved configuration. Speech authentication failures do not invalidate the summary provider. New archives default to `~/Documents/MeetingLog`; saved paths remain unchanged |
| One speech request per section | accepted | With a speech service, each recording, imported file, or capture track is one request, so speaker letters stay stable for the whole section. A section over 15 minutes that fails falls back to ten-minute windows; responses without usable timestamps are rejected |
| Local cleanup for speech transcripts | accepted | The speech service returns its clean style (fillers removed, words kept), which is the raw evidence. The readable transcript applies local rules instead of an LLM pass: leftover fillers go, a backchannel between two turns of the same other speaker goes unless it answers a question, and that speaker's fragments are joined. A text model rewrote wording and dropped about 30% of content words in testing. Window-fallback seams are not deduplicated |
| Ten-minute blocks with ten-second overlap | accepted | Chat-model transcription, and the speech fallback, use windows; every block must succeed before final Markdown is written |
| Transcript is evidence | accepted | Unsupported decisions are empty; unsupported context and reasons are empty strings |
| Folder-owned projects | accepted | Users create Unicode project folders and choose the destination per recording in the panel; selection uses its relative path; a missing destination requires an explicit replacement |
| Human-readable meeting folders | accepted | New meetings use `MMddyyyy-<short-title>` and numeric collision suffixes without migration of development archives |
| Recoverable meeting deletion | accepted | The main panel lists three recent completed meetings below any pending ones; clicking a meeting opens it in Meeting summaries, and its action menu holds Regenerate, Move, Show in Finder and Move to Trash. Deleted meetings move to the macOS Trash with Undo; Settings moves discarded pending sessions to the Trash as well |
| Markdown owns project context | accepted | `<project>/meeting_context.md` supplies names, jargon, aliases, and project-specific instructions |
| Compressed media is retained | accepted | Temporary chunks and imported original copies are deleted only after the final audio and Markdown archive succeeds |
| Zero third-party packages | accepted | A new package requires an observed missing native capability |
| Independent audio and video scope | accepted | System audio selects all Mac audio or one application; the Apple picker selects optional screen video |
| Plain app-preference API key | accepted | The personal app stores its configured API key unencrypted in the current user's preferences instead of Keychain |
| Native settings window | accepted | Archive and AI provider configuration stay out of the recording panel; the panel reaches it through the More menu, which also holds Quit and stays available while recording and saving |
| Recording precedes AI configuration | accepted | Missing provider configuration leaves a recoverable local session and never blocks capture |
| Core Audio owns system audio | accepted | System audio uses its dedicated privacy permission; ScreenCaptureKit is requested only for optional video |
| Timer-led recording panel | accepted | The panel shows a large elapsed timer, the fixed destination and per-track live meters while recording; after Stop it shows an explicit saving state with the frozen final duration and real mixing progress until the session is handed to processing. The menu bar uses static symbols (the recording symbol only while capturing, never while saving) because self-updating SwiftUI content in a `MenuBarExtra` label caused an unbounded redraw loop on macOS 26 |
| Explicit saving phase | accepted | Stop freezes the timer and disables recording until tracks are stopped and mixed; saving is its own phase so the menu bar never claims recording and previews stay off. Recordings under 10 seconds are still discarded |
| Explicit partial recovery | accepted | A permanent preparing/ready receipt records complete versus system-only mixing before media publication; excluded original tracks and fixed bilingual warnings survive archiving and regeneration |
| Microphone track identifies the recording user | accepted | Complete captures transcribe computer audio and microphone separately; microphone turns are always labeled `Me`, trading one extra audio upload per window for deterministic attribution. The speech service does not diarize the microphone track, so other people audible on it are also labeled `Me` |
| Simplified Chinese, Roman-letter names | accepted | Transcripts stay in the spoken language with Chinese normalized to Simplified characters; personal names use confirmed spellings or Pinyin because characters cannot be verified from sound |
| Generic prompts | accepted | Prompts state classification rules without examples from specific meetings; meeting-specific cases belong in evaluation material, not in every request |
| Inline panel feedback | accepted | The menu bar panel uses inline notices, Undo, confirmations, processing and failure cards in the Recent list, and an inline microphone no-input warning instead of modal alerts; completion, failure and no-input episodes use notifications instead of opening Finder |
| Structured processing stages | accepted | The processor reports prepare, transcribe (completed/total), clean, summary, evidence, Chinese and complete with a readable detail; the panel shows them as a six-segment bar |
| Microphone no-input warning | accepted | Warns only when an included microphone reports ≤ −96 dBFS (digital silence, below one 16-bit step) for 30 s during recording; the meter scale bottoms out at −60 dBFS and cannot distinguish a quiet room. It does not claim the user is muted, because app-level mute in Zoom does not silence the OS input. Each episode shows the inline warning; two seconds of input end it, so a crackle or gated word does not re-arm it, and notifications are at least five minutes apart |
| List-only summaries | accepted | Action items are written as a list with Owner, Deadline, context, and Evidence lines, like decisions, because Markdown tables paste poorly into chat and notes. Meeting summaries shows both this list and legacy tables as action cards |
| Markdown-derived summary view | accepted | Markdown stays the only stored summary format. Meeting summaries parses it into typed sections, classifying translated Chinese headings by keyword, and renders evidence references as chips; a section it cannot represent losslessly renders as generic Markdown, so edited and legacy summaries never lose content |
| Original transcription owns summary evidence | accepted | Drafts, review and line references use raw transcription; only old archives without it fall back to the readable transcript, with the source stated explicitly |

Prompt changes and evaluation criteria are documented in [prompt quality](prompt-quality.md); project authors can use the [context template](templates/project-context.md).

## Summary regeneration

Saved meetings expose regeneration through the Meeting summaries toolbar and each recent meeting's action menu. Generation sends only the existing transcript and current global/project context through the draft and evidence-review steps. Users compare the current and proposed Markdown before explicitly saving; generation and cancellation do not replace files.

Saving preserves the existing date, directory, transcript, and media. The proposed summary includes a regenerated full title, and the meeting list reads that title from Markdown. It derives the project from the current folder and rejects a preview if the summary, transcript, or context changed meanwhile. Before atomic replacement, `.summary-history/<revision-id>/` retains `previous.md`, `replacement.md`, and `provenance.json` with the exact prompts, context, endpoint and model (never the API key). A previous summary can be restored by copying `previous.md` back to `summary.md`.

Raw and readable transcription are checked separately, including file addition or removal; the recovery receipt also participates in conflict detection. The evidence source is saved in provenance and both summaries. We retain advisory reference matching: using the original transcription prevents editorial changes from becoming self-validating evidence, but does not prove that transcription or model interpretation is factually correct.

## Operational summary evidence

The schema separates milestones, open questions, deferred work, and infrastructure/documents. Prompts request transcript line references and supporting quotes for these entries, actions, and decisions. Reference checking is advisory: missing references or unmatched quotes never block generation or saving. Unmatched references are labeled unverified and a concise note is added to Needs verification. A matching quote establishes source correspondence, not whether it semantically proves a claim. The review pass checks coverage as well as unsupported claims, with distinct event/transition timings and explicit access deadlines.

Transcript prompts number original lines and scope anonymous speaker labels per section. With a speech service a section is normally the whole recording or file. They do not claim to identify voices across chunks or recover paths visible only on a shared screen. Empty project context is flagged in the regeneration window. Full titles remain intact in Markdown; only folder names have a UTF-8 byte budget. Initial summaries retain exact prompts and provider/model in `summary-provenance.json`; regenerated summaries retain them with the revision history.
